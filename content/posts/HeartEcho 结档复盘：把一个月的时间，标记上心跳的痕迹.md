## 一、 基石上的暗礁：数据层与契约

项目开局，我的任务是把 10 张核心表翻译成 GORM 结构体。这听起来是最没有技术含量的活，却埋下了最危险的雷。

### 1. 幽灵外键：静默的越权与污染

最初，我按照常规习惯，把主键 ID 定义成了 `type:bigserial`。
跑 `AutoMigrate` 建表，一切顺利。但当我们尝试插入数据时，诡异的事情发生了：在给 `personas` 表插入一条数据、且忘记传 `user_id` 时，数据库居然没有报错。

排查了半天，发现 `personas.user_id` 上凭空多出了一个 `nextval` 序列。这意味着，如果代码有 bug 漏传了外键，数据库会静默地给它分配一个不存在的自增 ID。

**真因**：GORM 在建立关联时，会把被引用主键的 `DataType` 复制给外键字段。`bigserial` 包含了序列属性，导致外键被污染。
**解法**：将所有的 GORM ID tag 全部改为 `type:bigint;autoIncrement`，严格禁止 `bigserial`。这属于“不查源码永远不知道”的底层坑。

### 2. 跨语言契约的“闭门羹”：422 错误

在实现主动消息和情绪分析时，Go 需要向 Python 发送当前的情绪状态。我顺手在 Go 的请求体里加了一个 `FamiliarityLevel` 字段，结果 Python 直接返回了 `422 Unprocessable Entity`。

去看 Python 的代码，才发现 Pydantic 严格配置了 `extra="forbid"`（禁止多余字段）。任何多传的键值都会被无情拦截。

**解法**：我们不想破坏已经冻结的请求体契约。于是我让 AI 写了一段 Hack 逻辑：把情绪指令以自然语言的形式，拼接到 `SpeakingStyle` 字符串的尾部（如：`温柔\n本轮回复要求：请优先共情`）。Python 拿到后原样塞进 System Prompt，完美绕过了 422 限制，还实现了功能。

> **教训**：多语言协作中，不要相信“顺便加个字段”的侥幸。契约必须精确到每一个 JSON Key。

## 二、 SSE 流式对话：跨越四层的“便秘”救援

为了让 AI 聊天有打字机的拟真感，我们用 SSE（Server-Sent Events）。但这条链路横跨了 **浏览器 -> Nginx -> Go -> Python** 四层。任何一层配置失误，打字机就会变成“等待十秒，一次性蹦出一大段”。

### 1. Nginx 的“好管闲事”
本地测试时流式好好的，一上云就完蛋。
**真因**：Nginx 默认开启了 `proxy_buffering`，它觉得你一点点吐字太慢，非要等攒够一大块再发给浏览器。
**解法**：在 `nginx.conf` 的 `/api` 路由里，强制加上 `proxy_buffering off;` 和 `X-Accel-Buffering: no`。

### 2. Go 的“矜持”
就算 Nginx 关了，前端还是卡顿。
**真因**：Go 的 HTTP Response 写入有缓冲区。你往 `c.Writer` 里写，不主动 `Flush`，它就不发。
**解法**：在每一次 SSE 事件写出后，强制调用 `c.Writer.Flush()`。一旦断开连接，立刻触发 `AbortController`，防止 goroutine 泄漏。

## 三、 智能体进阶：向向量检索与朋友圈进化

P2 阶段，我们决定给赛博女友换上真正的“大脑”。

### 1. 向量库的“跨墙搬运”
我们引入了 ChromaDB 来做语义召回，但这需要加载一个 200 多 MB 的 HuggingFace 模型。
国内云服务器的网络环境大家懂的都懂。直接拉取，超时；配置镜像源，依然超时。

**终极解法**：
1. 在我本地电脑上把模型跑通，找到 `onnx_models` 缓存目录。
2. 把文件夹打包成 `model.zip`。
3. 用 `scp` 传到服务器。
4. 启动空壳容器，用 `docker cp` 强行把模型塞进容器挂载的 volume 里。
5. 重启容器，世界安静了。

同时，向量库的 metadata 必须严格带上 `user_id` 和 `persona_id`。如果只带人设 ID，A 用户的 1 号人设就会召回 B 用户 1 号人设的记忆——这在情感陪伴应用里是灾难级的穿帮。

### 2. 朋友圈：从死模板到“上下文感知”
原先的朋友圈，是一天发 5 条固定的“今天天气真好”。我们把它改成了 LLM 驱动：
发圈前，代码会偷偷去 `chat_messages` 表里捞出最近 5 条聊天记录，扔给大模型。
于是，当我吐槽“最近吃辣肚子疼”，没过多久，朋友圈就刷出了一条：“某人天天吃辣还不听劝，现在好了吧（无奈）”。

但这引发了一个极其吓人的连锁反应：**赛博刷屏**。
有一次测试，我把定时任务间隔改成了 10 秒。结果系统瞬间“高潮”，半小时之内给所有 AI 刷了几百条朋友圈。我立刻在业务层加了硬限制：**日上限 5 条，两次间隔必须 ≥ 3 小时**，彻底废除了用 `TICKER` 频率当节流器的偷懒做法。

## 四、 前后端交锋：多态主题的极限拉扯

为了让简历更亮眼，我们做了 5 套主题：亮色、暗黑、青春疼痛文学、星夜、薄雾青。

### 1. 纯 CSS 实现的“日系小说”
“青春疼痛文学”主题是我设定的：大面积的蓝天白云、毛玻璃卡片（`backdrop-filter: blur(15px)`）、衬线字体、微弱的疼痛红强调色。
**踩坑**：毛玻璃效果极吃性能。在移动端（<768px）开启多个磨砂卡片会导致掉帧。于是我们用了媒体查询，在窄屏自动关闭 `backdrop-filter`，改为高不透明度的背景。

### 2. 防白屏闪烁
本地测试主题切换很丝滑，但刷新页面时，如果是暗黑模式，会先闪一秒白屏。
**解法**：在 `index.html` 的 `<head>` 里内联了一段原生 JS，在 React/Vue 挂载前，先读取 localStorage，直接给 `html` 标签打上 `class="dark"` 或 `theme-pain`。

## 五、 云端排雷：从 2C2G 的绝望到上线

部署，是压垮无数独立开发者的最后一根稻草。

### 1. 内存溢出（OOM）
2核2G 的服务器，跑 Postgres、Go、Python 和 Nginx 四个容器。执行 `docker compose up --build` 时，Go 编译 + npm 打包同时进行，内存瞬间打满。
**解法**：在服务器上建了 4G 的 Swap 虚拟内存。这就是拿硬盘当内存用，虽然编译慢一点，但至少不会在执行一半时被 Linux 内核无情 `Kill`。

### 2. Dockerfile 缓存失效
每次改一点点 Go 代码，一构建，发现又要重新下载十几分钟的 Go module 和 Python pip 包。
**真因**：Dockerfile 里写的是 `COPY . .`，一旦源码变化，这一层的缓存就废了，后面的 `RUN go mod download` 也会跟着重新跑。
**解法**：把依赖文件单独拷贝：`COPY go.mod go.sum ./` -> `RUN go mod download` -> 再 `COPY . .`。这样只要依赖没变，永远走秒级缓存。

### 3. 死锁的定时器
“朋友圈自动生成”的任务使用的是 `time.NewTicker`。测试的时候它死活不触发。
排查了一下午，发现 `time.NewTicker` 是**等满一个完整的 Interval 才会执行第一次**。我设的是 30 分钟，重启后端之后，它真的傻等了 30 分钟。
**解法**：在 `Run` 方法启动时，先立刻 `scanOnce` 一次，再进入 Ticker 循环。

## 六、 给 AI 当“主刀医生”的自我修养

这个项目做完，我最大的感触不是技术，而是**在 AI 时代，如何验收 AI 的代码**。

AI 有个极其致命的毛病：**它总是倾向于给你一个看起来最合理的解释，而不是最可验证的解释。**

当我说“情绪分析没生效”时，它会告诉我：“可能是 Python 的 ASGI 服务器缓冲了、或者是跨域拦截了、或者是 Docker 网络问题。”
它列了 5 个可能性，全都有理有据。但最后我自己去查数据库，发现 `emotion_label` 字段是 NULL。
**根本原因是它忘了把 UPDATE 语句里的 `user_id` 加上，导致更新命中了空集。**

从那以后，我总结了三条铁律：

1. **不要听解释，看计算值**。CSS 没生效，不要听它分析特异性，自己去 F12 里看 `getComputedStyle` 算出来到底是多少。
2. **一次只让它改一处**。它很喜欢“顺手把旁边五个文件也优化了”，一旦出问题，你连回滚都不知道回哪一步。
3. **必须自己写测试脚本**。它说单元测试全绿，不代表逻辑是对的。我会用 `curl` 直接打接口，甚至查数据库确认数据真的落盘了，才算通过。

项目已封版归档。回头看，这一个月最大的收获并非掌握了多少新框架，而是学会了在 AI 时代，如何作为一名工程师去主导架构、控制边界，以及做最终的“验收方”。
